Overview

Personal Cloud is a self-hosted cloud storage platform designed to provide users with a private and centralized environment for storing, managing, and accessing their files.

The primary objective is a cloud-storage solution deployed and managed independently using Docker containerization. Instead of depending entirely on third-party providers, the platform gives users a controlled environment where storage services are hosted and managed by the person or organization that runs it.

Screenshots

Problem statement

The gap

Traditional cloud-storage platforms provide convenient file storage, but users have limited control over the underlying infrastructure, deployment environment, and data-management architecture. Personal Cloud addresses this with a self-managed storage environment where the application and its supporting services run as isolated containers.

Objectives

  • Provide centralized personal file storage.
  • Enable access to files through a unified platform.
  • Containerize the application for simplified deployment.
  • Separate application services from the host system.
  • Provide a scalable foundation for more cloud-storage features.
  • Improve portability between development and deployment environments.
  • Establish a foundation for secure, self-managed data storage.

Core features

File management

The platform is built around the common cloud-storage operations.

  • Upload files
  • Download files
  • Store files
  • Organize files
  • Access stored files
  • Manage stored data

Dockerized deployment

Docker packages the application and its dependencies into containers, which delivers:

  • Consistent deployment environments
  • Easier installation
  • Service isolation
  • Portability between hosts
  • Simplified configuration
  • Easier application maintenance

Get started

Personal Cloud is open source and runnable in minutes with Docker. Clone the repository and follow the README.

1 git clone https://github.com/Rizirfan/personal-cloud
2 cd personal-cloud
3 docker compose up
docker compose up -d
docker ps
# app container  ->  storage service container  ->  persistent volume

Made to be used. Fork it, run it, adapt it. The exact ports, environment variables, and compose services are documented in the README, so anyone can self-host their own private cloud.

Architecture

Requests flow from the user down through the application into persistent storage, with each layer containerized.

User Web / Application Application Container Storage Service Container Persistent Storage User Files

The system is organized as independent services. Persistent Docker volumes keep stored data alive even when application containers are recreated. 

Docker Host
├── Application Container
│     └── Cloud Storage Application
├── Database Container
│     └── User / Application Metadata
└── Storage Volume
      └── Uploaded Files
